<details>
<summary><b>▸ Lab rules / how I like to build</b></summary>

1. Start with a real problem or an interesting question.
2. Ship the smallest version that proves something.
3. Keep code readable: typing, tests, sensible structure and useful logging.
4. Document the decisions, not just the installation commands.
5. Make it runnable by someone other than me.
6. Iterate. And have fun with it.

</details>
